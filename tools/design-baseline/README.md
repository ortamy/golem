# design-baseline — защита от визуальных регрессий (Этап 0)

Скриншот-базлайн Research Lab: матрица **тема × маршрут** для сверки до/после рефакторинга дизайна.

## Матрица

- Темы: `light`, `white`, `dark` (ключ localStorage `golem_theme`)
- Маршруты: `dashboard`, `manifest`, `states`, `dictionaries`, `researches`
- Вьюпорт 1440×900, fullPage, deviceScaleFactor 1

## Использование

```bash
cd tools/design-baseline

npm run baseline            # снять/переснять эталон (тег по умолчанию v0)
node screenshot.mjs v1      # снять текущее состояние под тегом v1
node compare.mjs v0 v1      # попиксельная сверка + отчёт + хит-карты дрейфа
```

## Вердикты сравнения

- `OK` — расхождение в пределах допуска (по умолч. ≤ 0.5% пикселей)
- `DRIFT` — превышен допуск; PNG-хит-карта в `diff/<A>..<B>/`
- `SIZE` — изменился размер страницы (сдвинулся поток верстки) — решает ревьюер
- Код выхода: 0 = чисто, 2 = есть дрейф/аномалии (удобно для CI)

## Как это работает

- Запуск по `file://` без HTTP-сервера (правило единственного сервера из CLAUDE.md);
  Chrome запускается с `--allow-file-access-from-files`, чтобы работали относительные `fetch()` данных.
- Используется системный Chrome (`channel: 'chrome'`) через `playwright-core` — браузеры не скачиваются.
- Свежий контекст на каждый кадр: чистый `localStorage`, тема проставляется init-скриптом.
- Ошибки консоли пишутся в `baseline/<tag>/errors.log`.

## Допуски

Порог различия одного пикселя (YIQ, `threshold`) и допуск на кадр настраиваются:

```bash
node compare.mjs v0 v1 --threshold 0.1 --max-diff 0.3
```

При намеренных изменениях (рефакторинг этапов 1–8) ожидаем DRIFT < допуска после ревью хит-карт;
подтверждённый новый вид фиксируется как новый тег базлайна.

## Эпохи съёмки (сравнивать только внутри эпохи)

- **Эпоха А** (`v0`–`v6`): сеть жива, CDN-вебшрифты загружены.
- **Эпоха Б** (`v7+`): детерминированный офлайн — скриншотер всегда режет внешние
  http(s) через `context.route`, шрифты системные; кадры не зависят от сети.
- Межэпоховое сравнение даёт массовый ложный DRIFT в текстовых зонах — запрещено.
- Причина перехода: блокирующий CDN `marked.min.js` из `<head>` вешал парсер
  при мёртвой сети; переведён на локальные `js/libs/…` c `defer`
  (попутная починка устойчивости самого приложения).
- Каноническая база эпохи Б: тег `v7` (этап 6 — навигация).

## Проба этапа 6 — навигация (stage6-nav.mjs)

Атрибуционная проба A/B: A = кадр эпохи v7 (модуль активен), B = тот же кадр с
заблокированным js/nav-enhance.js, снятый в той же офлайн-среде. Попиксельная
разница обязана жить только в зоне левой навигационной рейки.

    node stage6-nav.mjs                  # 9 ассертов + зональные диффы по 11 маршрутам
    node stage6-nav.mjs --shoot          # переснять B-кадры (офлайн ~25 c/кадр)
    node stage6-nav.mjs --only X --shoot # точечная пересъёмка одного маршрута
    node stage6-nav.mjs --fill-a         # добор отсутствующих A-кадров в эпоху v7

Ожидаемый дрейф: ~16.5 тыс. px на маршрут (0.1–1.2% в зависимости от высоты
страницы) — иконная рейка на всю высоту сайдбара. Дифф за пределами левой
полосы = дефект замены. Хит-карты: diff-stage6/.

Ассерты (9): фильтр в сайдбаре; >=20 инлайн-SVG; 0 старых PNG в пунктах;
Ctrl+K открывает палитру; палитра содержит 24 пункта; Escape закрывает из
любого фокуса; клик по хедер-поиску открывает палитру; фильтр скрывает
непопадания; Enter из палитры ведёт в валидный раздел.

### Побочная находка инструмента (исправлена)

Блокирующий CDN `<script src=...marked.min.js>` в <head> при недоступной сети
замораживал парсер до таймаута соединения: приложение не стартовало вовсе.
Заменён на локальную копию `js/libs/marked.min.js`. Все теги v7 и далее
снимаются в стабильной офлайн-эпохе (вебшрифты абортятся route-перехватом).
