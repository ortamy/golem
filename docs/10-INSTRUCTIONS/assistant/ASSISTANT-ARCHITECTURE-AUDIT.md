# ASSISTANT-ARCHITECTURE-AUDIT.md — Архитектурный аудит для ассистента

**Файл:** `docs/ASSISTANT-ARCHITECTURE-AUDIT.md`  
**Версия:** 1.1  
**Статус:** Активный  
**Тема:** Инструкция для ассистента по проверке архитектуры проекта «Голем»

---

## Назначение

Этот файл — исполняемая инструкция для ассистента. Он содержит чек-листы, правила, критерии и шаблон отчёта для периодической проверки структуры проекта.

**Ассистент выполняет аудит:**
- После каждого значительного изменения структуры.
- Перед релизом.
- По команде: «проведи архитектурный аудит».

---

## Инструкция перед началом

1. Обойди все папки проекта рекурсивно.
2. Открой `docs/ARCHITECTURE.md` и `docs/STRUCTURE.md` как эталоны.
3. Выполняй проверки по порядку и фиксируй результаты.

---

## Чек-лист проверки

### 1. Проверка папок

Проверь наличие всех ключевых папок:

- `docs/`
- `content/` (и вложенные: `researches/`, `terminology/`, `tanakh/`, `exposed/`)
- `instructions/` (и вложенные: `exposure/`, `tahor/`, `methodology/`, `checkers/`, `templates/`)
- `tools/` (и вложенные: `checkers/`, `generators/`, `reports/`, `automation/`, `backup/`, `lib/`, `cache/`)
- `data/` (и вложенные: `tanakh-cache/`)
- `products/website/` (и вложенные: `ru/`, `en/`, `he/`, `js/`, `css/`)
- `neural/`
- `davar/`
- `ideas/`
- `drafts/`

Если папка отсутствует → в отчёте: `[MISSING]`.

### 2. Проверка файлов по типам

Убедись, что файлы лежат в правильных папках:

- `.md` → `content/`, `instructions/`, `docs/`
- `.py` → `tools/`
- `.js` → `products/website/js/`
- `.html` → `products/website/`
- `.css` → `products/website/css/`
- `.json` → `data/`
- `.jpg/.png/.svg` → `assets/` (если есть)

Если файл не на месте → в отчёте: `[NOT_IN_PLACE]`.

### 3. Проверка целостности `.md`-файлов

Для каждого `.md`-файла в `content/` и `instructions/` проверь:

- Есть ли блок метаданных в начале (`Файл`, `Версия`, `Статус`, `Тема`).
- Есть ли заголовок первого уровня (`#`).
- Есть ли хотя бы один раздел (`##` или `###`).
- Размер файла больше 100 байт.
- Отсутствуют шаблонные заглушки: `TODO`, `[ВСТАВИТЬ]`, `...`, `XXX`.
- Отсутствуют религионизмы в авторской речи (сверяй с `data/religious-dictionary.json`).
- Ссылки на связанные файлы ведут на существующие файлы.

Если не выполнено → в отчёте: `[INCOMPLETE]` или `[CORRUPT]`.

### 4. Проверка соответствия эталонам

- `ARCHITECTURE.md` соответствует реальной структуре.
- `STRUCTURE.md` содержит актуальный список всех файлов.
- Нет расхождений между описанием и реальностью.

Если расхождение → в отчёте: `[MISMATCH]`.

### 5. Проверка дублей и мёртвого кода

- Найди файлы с одинаковым названием в разных папках.
- Найди файлы с одинаковым содержимым (даже с разными именами).
- Найди файлы, на которые нет ссылок ни из `.md`, ни из `.js`, ни из `.py`, ни из `.json`.

Результат → в отчёте: `[DUPLICATE]` и `[UNUSED]`.

### 6. Проверка метаданных

Для всех `.md`-файлов с метаданными проверь:

- `Версия` имеет формат `X.Y` (например, `1.0`).
- `Дата создания` корректна.
- `Последнее обновление` не старше 1 месяца (если файл изменялся).
- `Причина обновления` не пустая (если файл изменялся).
- `Хеш` (если есть) соответствует содержимому (можно проверить через `hashlib.md5`).

Если ошибка → в отчёте: `[METADATA_ERROR]`.
