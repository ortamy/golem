## 1. ЦЕЛЬ

Сделать документацию `docs/` **самопроверяемой** и **навигабельной**:

1. расхождения «шапка ↔ фактический путь», битые ссылки и дрейф индекса ловятся машиной в CI, а не ручными проходами;
2. читатель за один взгляд отличает актуальный документ от исторического;
3. дубли и противоречия (например, «16/17 состояний») устранены;
4. INDEX.md, обложки разделов и статистика генерируются из фактического состояния папки.

## 3. РЕШЕНИЯ ПО ПАКЕТУ

### 3.1. Машинная валидация

Новый инструмент `tools/check-docs.py` (только stdlib, стиль проекта: argparse, юникод-вывод):

| Проверка | Уровень | Действие |
| --- | --- | --- |
| «Файл:» в шапке ≠ фактический путь (с учётом `docs/` и относительных форм) | error | `--fix` переписывает путь в шапке |
| Битые Markdown-ссылки `](...md)` внутри `docs/` (регистрозависимо, без кодовых блоков) | error | отчёт |
| Дрейф навигации: INDEX.md, README-обложки, STATS.md ≠ генератор | error | перегенерировать `generate-docs-index.py` |
| Дубли первых заголовков (H1) по корпусу | warning | отчёт |
| Пустые элементы в «Связанные файлы» (`` ` ` ``) | warning | отчёт |
| Неизвестное значение «Статус:» | warning | отчёт |

Exit-код: 0 — чисто; 1 — есть error. Прогон: CI-workflow `.github/workflows/docs-check.yml` на `paths: docs/**, tools/check-docs.py, tools/generate-docs-index.py` + локально `python tools/check-docs.py check`.

### 3.2. Жизненный цикл документов

- Разрешённые статусы: `Активный | Исторический | Заготовка | Концепция`.
- Маркер исторического документа — строка сразу под H1:
  `> ⚠️ ИСТОРИЧЕСКИЙ ДОКУМЕНТ — описывает устаревшую структуру. Актуальное состояние: <ссылка>.`
  + поле «Статус: Исторический» в метаданных.
- Мёртвые гайды физически переносятся в `docs/99-HISTORICAL/` (архив, сортируется последним).

### 3.3. Переносы (структура)

| Файл | Было | Стало |
| --- | --- | --- |
| PALEO-STANDARD.md | docs/06-METHODOLOGY/ | docs/04-STANDARD/ |
| PALEO-TRANSLATION-PRINCIPLES.md | docs/06-METHODOLOGY/ | docs/04-STANDARD/ |
| PALEO-TRANSLATION-PROTOCOL.md | docs/06-METHODOLOGY/ | docs/04-STANDARD/ |
| CODING, GIT, SETUP, FAQ, SECURITY, SEARCH, CONTRIBUTING, COLLABORATION, WORKFLOW-RESEARCH, TROUBLESHOOTING (.md) | docs/09-GUIDES/ | docs/99-HISTORICAL/ |

Перенос PALEO-файлов **чинит** ~90 ссылок корпуса (они уже указывают `04-STANDARD`) и не требует правки текстов. На «мёртвые» гайды ссылок из актуальных файлов нет — перенос безопасен; их внутренние шапки «Файл:» приводятся к новому пути `check-docs.py --fix`.

### 3.4. Пометки без переноса

- `CHECKERS.md`, `RESEARCHES-REPORT.md` — остаются на месте, получают статус «Исторический» + баннер со ссылкой на `DOCS-AUDIT-2026-09-02.md`.
- `ICONS.md` — статус «Исторический» + баннер: актуальная карта — `ICON-MAP.md`.
- `WEB-INTERFACE.md`, `WEBSITE.md`, `RESEARCH-LAB.md` — статус «Исторический» + баннер: актуальная карта Research Lab — `RESEARCH-LAB-MAP.md` (внутри `11-PRODUCTS`).
- Учитывая правило проекта «не выдавать гипотезу за факт»: исторические документы **не удаляются**, только помечаются.

### 3.5. Устранение противоречий и дублей

- `GOLEM.md`: «17 состояний» → «16 состояний» (канон — MANIFEST/STATES.md).
- `07-MECHANICS/README.md`: ссылки на файлы букв — в верхний регистр (совпадает с фактическими именами).
- Эталонные списки (22 буквы, состояния и т.п.) остаются в канонических документах (MANIFEST, PALEO-STANDARD, STATES.md); дубли в производных файлах ссылаются на канон, а не копируются.

### 3.6. Генерация навигации

Новый инструмент `tools/generate-docs-index.py` (stdlib):
- `docs/INDEX.md` — полная пересборка из ФС: разделы = папки 00–99, аннотация файла берётся из метаданных («Назначение/Тема/Описание») или первого H1;
- `docs/<раздел>/README.md` — обложка для разделов без README (существующие 00-START и 07-MECHANICS не трогаются);
- `docs/02-MANAGEMENT/STATS.md` — авто-статистика (число файлов/строк по разделам, распределение статусов) с пометкой «генерируется инструментом»;
- пересборка идемпотентна: `check-docs.py` сверяет файлы с эталонным выводом генератора (защита от дрейфа).

## 4. ПОРЯДОК ВЫПОЛНЕНИЯ

1. Инструменты: `generate-docs-index.py` → `check-docs.py` → workflow `docs-check.yml`.
2. Переносы файлов (git mv) + `check-docs.py --fix` шапок.
3. Баннеры и статусы исторических/устаревших документов.
4. Противоречия (16/17, регистр 07-MECHANICS).
5. Перегенерация навигации, прогон чекера до чистого результата.
6. Проверка: `git diff --check`, `git status --short`.
