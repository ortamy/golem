# ИДЕИ: СВЯЗКА ЛЕНДИНГА И RESEARCH LAB

**Файл:** `docs/ideas/LANDING-LAB-IDEAS.md`
**Статус:** бэклог идей
**Контекст:** идеи собраны после реализации мобильного лендинга, пайплайнов и интерактивных элементов Research Lab.
**Методологическая опора:** `docs/00-START/MANIFEST.md`, `docs/01-ARCHITECTURE/ARCHITECTURE.md`.

---

## Главная недостающая связка

Проекту нужен единый сценарий прохождения:

```text
знакомое слово → корень → палео-буквы → физическая функция →
механика слова → проверка перевода → сохранённый результат
```

Посетитель должен проходить этот путь за 2–3 минуты, не теряя связь между лендингом, документацией и лабораторией.

## Приоритет 1: быстрые улучшения лендинга

### Интерактивный путь слова

Добавить на первый экран поле:

```text
Введите слово → выбрать корень → увидеть палео-сборку
```

Показывать:

- корень;
- крупные палео-буквы;
- образ и функцию каждой буквы;
- последовательность действий;
- ссылку «Продолжить в лаборатории».

Связать с модулями `root-dictionary`, `paleo-builder` и `learn/paleo-trainer`.

### Интерактивное демо Мицраима

Развить текущую карточку Мицраима:

- тап по букве;
- подсветка текущего шага;
- переход между буквами;
- финальная последовательность: поток → захват → вершина → действие → поток;
- на desktop — hover и focus, на mobile — tap.

### Маршруты исследования

Показать четыре самостоятельных входа:

- начать с корня;
- найти подмену;
- собрать слово;
- проверить перевод.

Каждый вход ведёт в конкретный модуль лаборатории, а не в общий dashboard.

## Приоритет 2: связка с документацией

### Метод в действии

Сделать карточки методов из `docs/06-METHODOLOGY/`:

- этимологическая хирургия;
- палеографическая экспертиза;
- сравнительная семитология;
- образное картирование;
- разрыв цепочки перевода.

Каждая карточка содержит краткое описание, тип вскрываемой подмены, пример и ссылку на разбор.

### Визуальная карта слоёв

Расширить «Карту утрат» до маршрута:

```text
палео-образ → масоретский слой → греческая передача →
латинская передача → синодальный слой
```

Для выбранного слоя показывать:

- что добавилось;
- что исчезло;
- пример замены;
- ссылку на документ Research Lab.

### Один корень в день

Добавить регулярно меняющийся блок:

- буква дня;
- корень;
- палео-образ;
- физическая функция;
- пример слова;
- ссылка на разбор в лаборатории.

Блок можно связать с waitlist и будущим Палео-клубом.

## Приоритет 3: доверие и глубина

### Публичные кейсы исследований

Создать секцию кейсов с полным маршрутом:

- исходное слово;
- распространённый перевод;
- палео-сборка;
- найденная подмена;
- итоговая рабочая гипотеза.

Каждый кейс должен вести на полноценную страницу или в `research-library`.

### Источники и уровень уверенности

В публичных разборах показывать:

- корневой словарь;
- текстовый корпус;
- методический документ;
- степень уверенности.

Рекомендуемые статусы:

- зафиксировано;
- подтверждается;
- рабочая гипотеза;
- требует проверки.

Это поддерживает принцип из методологии: рабочая карта не выдаётся за единственную реальность.

## Приоритет 4: единая рабочая область

### Сквозной исследовательский маршрут

Объединить существующие модули в последовательность:

```text
Корень → Буквы → Палео-образ → Механика слова →
Сравнение переводов → Проверка подмен → Карточка исследования
```

На каждом шаге:

- сохранять состояние;
- показывать прогресс;
- давать кнопку «Продолжить»;
- формировать итоговый Markdown/JSON.

### Рабочая область исследования

Объединить идеи `board`, `clue-generator` и пайплайнов:

- перетаскиваемые наблюдения;
- корни и буквы;
- цитаты;
- найденные подмены;
- связи между наблюдениями;
- экспорт итоговой карты.

### Сохранённые маршруты

Добавить локальный раздел «Мои исследования»:

- последний открытый корень;
- последние разобранные слова;
- незавершённые пайплайны;
- история проверок;
- незавершённые исследовательские маршруты.

Хранение по умолчанию — локальное, без обязательного аккаунта.

## Приоритет 5: регулярное возвращение

### Еженедельная тема

Запустить последовательность тем:

- вода и поток;
- вместилище;
- связка;
- захват.

В каждой теме:

- буква;
- корни;
- фрагмент текста;
- мини-задание;
- тема для обсуждения в клубе.

### Разбор за 3 минуты

Формат короткой карточки:

- слово;
- привычное чтение;
- буквенная сборка;
- одна найденная подмена;
- один вопрос пользователю.

### Публичный журнал изменений

Добавить блок «Что добавилось в Golem»:

- новые корни;
- новые документы;
- новые пайплайны;
- новые инструменты;
- изменения методологии.

## Приоритет 6: развитие Палео-клуба

### Расширенная waitlist

После базового email добавить необязательный выбор интереса:

- изучать буквы;
- разбирать тексты;
- участвовать в живых сессиях;
- помогать проекту.

Данные подключать к Supabase после готовности backend-слоя. Локальная очередь должна продолжать работать без сервера.

### Клубный календарь

После открытия клуба показывать:

- ближайшие сессии;
- тему встречи;
- количество мест;
- ссылку на запись;
- архив прошедших разборов.

### Еженедельный код

Участникам waitlist отправлять:

- букву недели;
- короткую механику;
- ссылку на интерактивный разбор.

## Три ближайшие задачи

1. **Интерактивное демо Мицраима на главной** — быстро показывает уникальность проекта без перехода в лабораторию.
2. **Путь слова от корня до проверки перевода** — связывает существующие словари, сборщики, чекеры и результаты.
3. **Публичные кейсы исследований** — превращает документацию и внутреннюю методологию в понятный вход для нового посетителя.

## Ограничения реализации

- Сохранять терминологию и методологическое поле `MANIFEST.md`.
- Не выдавать рабочую гипотезу за установленный факт.
- Не требовать аккаунт для базового локального исследования.
- Переиспользовать существующие Vanilla JS-модули и маршруты.
- Новые данные и интерактивы сначала реализовывать в `apps/researchlab/` и публичном лендинге, затем обновлять `build/` сборкой.
