# Скорость агента без ущерба процессу

Канон: `.clinerules` §2 «Правило одного прохода», §3 MCP, §12, §15.
Этот файл — зачем и как, без повторного обхода репозитория.

## Диагноз

Задачи дорожают не из-за CSS, а из-за цикла «перечитать → перепроверить → пересказать историю».

1. Бесконечные resumption после compact: повторный поиск тех же файлов и полный `git diff`.
2. Рассинхрон протоколов инструментов: повтор тех же 50–200 строк.
3. Слишком широкие проверки на мелкую правку (Playwright, скрины 4 тем, поиск по всему репо).
4. `git diff` гигантов (`products/website/index.html`) зависает и возвращает обрезок.
5. Повторное чтение вместо конспекта.
6. Длинный ритуал «план → вызов → пересказ → снова план» на P0-фикс.

## Правила (качество не ослабляем)

**Один проход.** Локальная UI/CSS/строка: точное место → патч → `git status --short` + при JS `node --check` → стоп.

**Не возобновлять расследование.** После compact: 8–12 строк состояния (файлы, сделано, один шаг). Не начинать с «ищу X» в пятый раз.

**Читать узко.** Известный путь — ~40 строк. Класс найден — не искать по всему репо.

**Не диффить гигантов.** Диапазон или точечный поиск, не полный `git diff` лендинга.

**Лимит повторов.** Тот же инструмент + тот же запрос = максимум 2. Дальше смени метод.

**Playwright не «на всякий случай».** Только явная просьба visually/скрины или реальный слом вёрстки.

**Резать отчёты.** Простая задача: 5–8 строк. Before/after — большим задачам.

**Дробить сессии.** После этапа — compact или новый чат. Не смешивать несвязанные фиксы в одном бесконечном треде.

**Ноль инструментов** на запросы «напиши идею текстом», если код не трогаем.

**Две успешные проверки закрывают задачу.** Не искать третий способ убедиться.

## Что не отменяем

- Приоритеты `.clinerules` §1, сохранность дерева, Boy Scout в рамках задачи.
- `node --check` для затронутого JS, `git diff --check` по затронутым файлам.
- Smoke локально — только если пользователь просил.
- Браузерная проверка UI — когда правка реально меняет поведение/вёрстку или пользователь просил visually.
- ADR при триггерах §14.

## Практический режим

1 абзац плана → 1–3 точечных вызова → короткий результат.
Если файлы уже правильные после двух проверок — стоп.
