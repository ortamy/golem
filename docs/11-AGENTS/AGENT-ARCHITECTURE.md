1. ОБЩАЯ АРХИТЕКТУРА

Система построена по принципу «Оркестратор + Пайплайны». Запрос проходит через три слоя.

-------------------------------------------------------------
|  СЛОЙ 1: ВЕБ-ИНТЕРФЕЙС (Research Lab)                     |
|  Пользователь нажимает кнопку «Запустить агентов»         |
|  ↓                                                         |
|  СЛОЙ 2: API-СЕРВЕР (server.py / Flask)                   |
|  Принимает запрос, возвращает результат в JSON            |
|  ↓                                                         |
|  СЛОЙ 3: МУЛЬТИ-АГЕНТНАЯ СИСТЕМА (Python)                |
|  Оркестратор → Пайплайн → Агенты → Данные                |
-------------------------------------------------------------

2. СТРУКТУРА ПАПОК И ФАЙЛОВ

Все файлы находятся в папке products/agents/.

-- products/agents/main.py -- Точка входа для командной строки (CLI).

3. ОРКЕСТРАТОР (orchestrator.py)

Оркестратор принимает запрос и определяет, какой пайплайн запустить. Он работает по простой логике ключевых слов.

Если запрос содержит «разбери слово», то запускается pipelines.word_analyzer.
Если запрос содержит «сравни стих», то запускается pipelines.verse_comparator.
Если запрос содержит «собери исследование», то запускается pipelines.research_builder.
Во всех остальных случаях возвращается ошибка «Неизвестный тип запроса».

---

4. ПАЙПЛАЙНЫ (pipelines/)

Каждый пайплайн — это строго определённая последовательность вызовов агентов. Внутри каждого пайплайна агенты вызываются по очереди. Если агент возвращает пустой результат, пайплайн останавливается.

-- pipelines/word_analyzer.py -- Цепочка: researcher → semitologist → exposer → editor → collector.
-- pipelines/verse_comparator.py -- Цепочка: comparator → critic → editor → collector.
-- pipelines/research_builder.py -- Цепочка: flow_architect → connector → technical_writer → collector.

---

5. АГЕНТЫ (agents/)

Каждый агент находится в отдельном файле и выполняет одну строго определённую задачу. Агенты не знают о существовании друг друга. Каждый агент экспортирует функцию run(data), которая принимает данные от предыдущего агента и возвращает обработанный результат.

-- agents/researcher.py -- Ищет корни и стихи в roots.json через utils/context.py.
-- agents/semitologist.py -- Ищет параллели в аккадском, арамейском и угаритском языках.
-- agents/exposer.py -- Находит подмены в переводах (сравнивает LXX и Синодальный).
-- agents/comparator.py -- Сравнивает LXX, ТМ и кумранские свитки.
-- agents/critic.py -- Проверяет разбор на соответствие методологии «Голема».
-- agents/editor.py -- Приводит черновик к единому стилю проекта.
-- agents/collector.py -- Собирает результаты всех агентов в единый отчёт (JSON или Markdown).
-- agents/paleo_translator.py -- Переводит палео-буквы в образы и физические смыслы.
-- agents/writer.py -- Пишет документацию и оформляет Markdown-файлы.
-- agents/frontend.py -- Создаёт интерфейсы. Текущий статус: заглушка.
-- agents/ai_engineer.py -- Разрабатывает нейросетевые модули. Текущий статус: заглушка.
-- agents/validator.py -- Валидирует код, данные и исследовательские гипотезы. Текущий статус: заглушка.
-- agents/code_reviewer.py -- Проверяет код на соответствие MANIFEST.md. Текущий статус: заглушка.
-- agents/flow_architect.py -- Проектирует порядок вызовов агентов и поток данных. Текущий статус: заглушка.
-- agents/connector.py -- Связывает разрозненные исследования в единую сеть. Текущий статус: заглушка.

6. ДАННЫЕ (utils/context.py)

Файл context.py отвечает за загрузку и поиск данных. Он определяет все пути к корневым папкам проекта и работает с файловой системой.

-- load_roots() -- Загружает roots.json из папки researchlab/data/roots/.
-- find_root(query) -- Ищет корень по запросу в roots.json.
-- find_term_files(query) -- Ищет .md-файлы в content/terminology/ по имени или содержимому.
-- find_tanakh_verse_context(ref) -- Ищет упоминания ссылки на стих (например, «Берешит 1:1») в content/tanakh/.
-- load_instruction(rel_path) -- Загружает шаблоны инструкций из папки instructions/.
-- slugify(text) -- Преобразует текст в URL-дружественный формат.

7. API-СЕРВЕР (server.py)

Сервер написан на Flask. Он принимает POST-запросы на эндпоинт /run.

Запрос должен содержать JSON-тело с полем query. Например: {"query": "разбери слово Берешит"}.

Сервер передаёт строку запроса в orchestrator.run(), получает результат и возвращает его в формате JSON.

Запуск сервера производится командой python server.py в папке products/agents/. Сервер по умолчанию слушает порт 5000.

---

8. ИНТЕГРАЦИЯ С RESEARCH LAB (ВЕБ-ИНТЕРФЕЙС)

Чтобы сайт мог вызывать агентов, в Research Lab нужно добавить JavaScript-код, который отправляет POST-запрос на локальный сервер.

Пример кода для сайта:
fetch('http://localhost:5000/run', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ query: "разбери слово Берешит" })
})
.then(res => res.json())
.then(data => console.log(data));

Этот код можно поместить в карточку «AI-Агенты» или в любую другую точку интерфейса, откуда пользователь может отправлять запросы.

9. ЗАПУСК СИСТЕМЫ

Запуск через командную строку (CLI):
cd products/agents
python main.py "разбери слово Берешит"

Запуск через веб-API:
cd products/agents
python server.py

Сервер будет доступен по адресу http://localhost:5000/run.

Для работы системы необходимо сначала установить зависимости:
pip install -r requirements.txt

10. РАСШИРЕНИЕ СИСТЕМЫ

Чтобы добавить нового агента:
1. Создать файл agents/new_agent.py.
2. Определить в нём функцию run(data), которая принимает данные и возвращает результат.
3. Импортировать этого агента в нужный пайплайн.
4. Вставить вызов этого агента в цепочку внутри пайплайна.

Чтобы добавить новый пайплайн:
1. Создать файл pipelines/new_pipeline.py.
2. Написать в нём последовательность вызовов агентов.
3. В orchestrator.py добавить новое условие для запуска этого пайплайна.
